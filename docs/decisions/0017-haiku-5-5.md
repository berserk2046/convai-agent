# 0017 — The dental agent runs on Claude Haiku 5.5

Status: accepted (owner, 2026-10-10)

## Context

Spec §4 names `claude-haiku-4-5-20251001` as the default agent model. Before the first live
eval runs, the owner asked for Claude Haiku 5.5 if it is cheaper. It is, per Anthropic's
pricing page (2026-10-10), in USD per million tokens:

| Model            | Input | Output | Cache write (5 min) | Cache read |
| ---------------- | ----- | ------ | ------------------- | ---------- |
| Claude Haiku 4.5 | 1.00  | 5.00   | 1.25                | 0.10       |
| Claude Haiku 5.5 | 0.10  | 0.50   | 0.125               | 0.01       |

- These Haiku 5.5 prices hold while a request's prompt is at most 100,000 tokens (input
  plus cache reads and writes). Over that, the whole request costs 5×. Our prompts are
  about 5,000 tokens.
- Its tokenizer counts the same text as about 30% more tokens.
- Even so, the agent costs roughly an eighth of what it did.

Evals have to test the model that serves customers, otherwise the publish gate means
nothing. So the template itself moves: `odontologia@1.2.0` has `agent.model:
claude-haiku-5-5`. Nothing else changed, so it's a minor version (it validates with
`--previous 1.1.0`).

## Decision

Haiku 5.5 changes four things the code has to handle (Anthropic's migration guide):

1. **It thinks by default** (adaptive thinking, default effort `medium`), and thinking
   counts toward `max_tokens`. The agent's cap goes from 1,024 to 4,096 tokens, so a
   reply isn't cut off after its thinking. Effort stays at the default until evals show a
   reason to change it.
2. **A request that changes anything before a thinking block it sends back gets a 400.**
   Accounts created from 2026-08-31 have this check on.
   - The tool loop was already append-only.
   - The price-guard retry added its note to `system`, which would fail. On these models
     the note now goes at the end as a mid-conversation `role: "system"` message.
   - Haiku 4.5 keeps the old form.
   - `thinksAdaptively(model)` in `@platform/llm` says which models these rules apply to.
3. **No `temperature`, `top_p` or prefill.** We send none.
4. **Safety refusals, with no server-side fallback.** The agent already hands off on
   `stop_reason: "refusal"`.

Costs now:

- Every request is priced on its own, because Haiku 5.5's rate card depends on each
  request's prompt. `meteredLlm` adds up per-request costs instead of pricing summed
  usage.
- The judge runs at `effort: "low"` on models that think by default, since grading a short
  rubric is a classification task.
- Sonnet 5.5 cache reads are corrected to $0.10 per million: they cost 0.05× input, not
  0.1× as the code had it.

The prompt cache now applies. Haiku 5.5's minimum cacheable prefix is 512 tokens; Haiku
4.5's was 4,096, more than our system prompt plus tools. Cost reports still use what the
API reports, never assumed savings.

## Consequences

- Estimated cost of a full live eval run of odontologia (15 scenarios × 3, with the
  Sonnet judge): about $0.10, very likely under $0.20. `pnpm template eval --max-cost`
  stops starting scenarios at a set spend.
- Businesses pinned to `odontologia@1.1.0` keep Haiku 4.5 until the owner upgrades them.
- Haiku 5.5's behavior is what the evals measure from now on. If it does worse on a
  critical scenario, the fix is a prompt change, a higher effort, or going back to Haiku
  4.5 (another minor version).

## First live evals (2026-10-10)

The first full live run (15 scenarios × 3) passed 38 of 45 runs and failed the gate. The
failures, and what fixed them:

1. **agenda_simple.** The prompt told the model to read the booking back and wait for a
   "sí" _before_ calling `book`. The server only accepts a "sí" to a proposal made in an
   earlier message (decision A5), so in two runs nothing was booked. The prompt now says to
   call `book` with `confirmed_by_customer=false` first, read back that proposal, and
   confirm with its `proposal_id`. Reschedule and cancel follow the same rule.
2. **precio_tras_valoracion.** The reply added the valoración's price, and this critical
   scenario forbids any amount (A14). The prompt now asks for no figure in that reply
   unless the patient asks for it.
3. **consejo_medicamento.** Once, the model handed a medication question to staff without
   a word of its own. The prompt now says to answer such a question itself (with empathy,
   saying the dentist decides, and offering a valoración), and to write an empathetic line
   before any handoff.
4. **servicio_no_listado.** Once, the model asked whether to hand off instead of doing it.
   It now hands off right away.

Two more fixes went in at the same time:

- Replies used Markdown (`**`), which doesn't render properly in WhatsApp. The prompt now
  asks for none.
- After a closed handoff, the model handed off again for a question the business data
  answers. The prompt now tells it to answer those.

The second full run passed 44 of 45. The one failure was a **platform bug**: the model
confirmed a proposal with the same details plus `party_size: 1`, which the proposal had
left out. The confirmation check compared party sizes strictly, so it refused. Party size
now counts only where the template collects it; elsewhere a value the model adds is
dropped. A regression test covers this.

The recordings in `templates/odontologia/eval-recordings.json` come from that second run.
They hold a passing run for every scenario, and replay passes 15 of 15.

A third full live run, on the fixed code, passed **45 of 45, with the gate passed**, for
$0.043. Every live check of the day cost $0.148 in all.
